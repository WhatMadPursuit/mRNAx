# ADR-0003: Dual-FTO Method-Claim Guardrails (`CN119265214B` / `US20220269951A1`) & Wave 8 Three-Layer Clean-Room Traps

- **Status**: Accepted (2026-11-27)
- **Context**: Independent Wave 8 audit (`A-W8_rna_tools_reference_datasets_and_fto_snowball.md`) established two structural requirements for `mRNAx v2` (`commercial_clean`):
  1. **Sequence FTO != Method-Claim FTO**: Screening output sequences against `patent_fto_guard_v2.json` (`SequenceFTOGuard`) detects sequence/genus collisions on delivered UTR and poly(A) elements, but cannot determine whether the optimization algorithm itself practices a granted method claim:
     - `CN119265214B` Claim 1 (family `JP7892088B2`, `US20250092387A1`) claims partitioning an mRNA into a two-zone initiation region (`5'UTR` + preset-length N-terminal `CDS` prefix) and a main `CDS` body, optimizing the initiation region first for initiation efficiency, and subsequently optimizing the main `CDS` body with a composite initiation/CAI/MFE objective.
     - `US20220269951A1` (`CN114974428A`, `EP4682890A3`, LinearDesign) claims constructing per-residue codon DFAs, concatenating DFAs, intersecting the codon lattice DFA with a folding CFG, and searching the intersected grammar.
     - `US10898584B2` (CureVac) claims specific thresholded wild-type-to-synonymous GC/codon substitution steps coupled to synthesis.
  2. **Hidden Three-Layer & Transitive Dependency Traps**:
     - Permissive top-level wrappers can pull copyleft/restricted dependencies (`MultiStructRNA` MIT wrapper -> `varnaapi==1.1.1` `GPL-3.0` + `ViennaRNA`).
     - Open code can pair with restricted frameworks, weights, or training corpora (`Helix-mRNA` / `helical` `AGPL-3.0` + `CC-BY-NC-SA-4.0`; `UTR-LM` `GPL-3.0`; `GEMORNA`, `RiboNN`, `CodonBERT`, and `AIDO.RNA` non-commercial clauses; `RibonanzaNet` unverified standalone `.pt` weight license; `RhoFold+` non-commercial training corpus restriction).
     - Conversely, `EternaFold v1.3.1` (`BSD-3-Clause` standalone C++ binary + `BSD-3-Clause` `EternaFoldParams.v1`, zero `ViennaRNA` linkage) is eligible for `commercial_clean` base-pairing / unpaired-probability scoring (`RC-004`), provided structural probabilities are stored under their own metric schema rather than mislabeled as `ViennaRNA` thermodynamic MFE (`kcal/mol`).
- **Decision**:
  1. **Enforce Dual-FTO Separation & Honest Disclaimers**: Never emit blanket `"100% FTO"` claims. Track sequence-collision screening (`SequenceFTOGuard`) separately from algorithmic execution provenance (`MethodFTOAuditRecord` on `RunManifest`), flagging jurisdiction-specific patent counsel review prior to commercial clinical/manufacturing deployment.
  2. **Unpartitioned Full-Transcript Pareto Topology in `commercial_clean`**: `mRNAx v2` executes candidate generation via non-lattice synonymous bicodon/UTR proposal operators (`uses_dfa_cfg_intersection=False`) and evaluates whole transcripts simultaneously across multi-objective Pareto fronts without a two-zone `[5'UTR + CDS prefix]` -> `[CDS main body]` sequential optimization split (`optimization_mode="full_transcript_non_partitioned_pareto"`, `uses_two_zone_initiation_body_partition=False`).
  3. **Three-Layer + Transitive Dependency Gate**: Block `GPL-*`, `AGPL-*`, `LGPL-*` static/python copyleft (`varnaapi`), non-commercial weights/frameworks (`helical`, `GEMORNA`, `RiboNN`, `CodonBERT`, `AIDO.RNA`, `LinearDesign`), and unverified weight licenses (`RibonanzaNet` `.pt`) in `commercial_clean`, checking Code, Weights, Data, AND recursive `transitive_dependencies` on every registered component.
